# Stage 3 contract — approved final 700px vertical sketch storyboard

## Preflight (mandatory)
Read scene source, editorial and visual approved revisions, project context and references, then verify BOTH stage1.status and stage2.status are `approved`. A revision to causal facts or layout after approval invalidates downstream approval. Create exact panel roster P01..Pn with no duplicates or gaps, and a scene continuity checklist.

## Render style and content
Deliver a **low-fidelity storyboard**, never a finished illustration: rough pencil/ink sketch lines, sparse gray values, intentionally simple human figures and props, visibly distinct panel borders, staging and gestures readable at phone size. Preserve shot size and camera angle, silhouette and position continuity, direction of attention, focal evidence, essential plot text placeholders, gutters, reveal timing. No color rendering, polished lighting, photorealism, decorative typography or unrelated effects. If an essential word or text message cannot be reliably generated as pixels, reserve the correct box and overlay accurate readable text with a deterministic editor; do not fake text.

Use the available image-generation tool when accessible; follow its tool contract and provide the exact approved scene/panel map, not a vague art-style request. Use an image editor or image processing tool for cropping, text overlays and 700px export; **do not label a mockup as generated by a model unless it was**. The source artwork may be any width; every final delivered segment and master MUST be exported at **exactly 700 physical pixels wide**. Vertical height is not capped by the skill, subject only to tool/memory limits.

## Split and stitching
If image generation cannot represent an entire scene legibly or would exceed size limits:
- Break at clean panel boundaries into `storyboard-part-01.png`, `storyboard-part-02.png`, etc.
- Each part **700 pixels wide**, variable height; same sketch line weight, panel labels and character identity, without repeated/omitted panels.
- Do not splice through a panel. When feasible create `storyboard-full.png` with parts stacked in order (700px wide), preserving approved gutters exactly once; if impractical, parts collectively form the deliverable. Do not downscale an enormously tall sheet until panels become unreadable.
- Write `panels.json` mapping `Pxx` → source beat, image part, top/bottom y (if measured), approved function, and scene ID. Record whether stitching was performed.

## Technical verification
Before delivering:
1. Decode each PNG (or SVG image fallback) and verify width == 700; record true pixel height and mode. For SVG, set `width="700"` and a numeric `viewBox`, verify SVG parses and renders accurately; use SVG only when supported by viewer and clearly label format.
2. Check panel roster coverage and sequence against the approved visual plan.
3. Check legibility of key clues/text, character identity, props, geographic continuity and intended reveals at phone size.
4. Ensure no unapproved new plot events or spoilers.
5. Commit images and metadata to GitHub then read back verifiable file metadata. Only declare success when both generation and upload succeed.

Use `scripts/validate_storyboard.py` from the skill package for width, image and manifest checks where available. Any failed check keeps `stage3.status=needs-revision`.

## Github binary upload
Text plans: GitHub `create_file/update_file`.
PNG via GitHub Git data API: base64-encode actual PNG bytes; call `create_blob({content:<base64>,encoding:"base64"})`; create a tree entry `{path, mode:"100644", type:"blob", sha}` against the current base tree; create commit and advance the main ref with checked `expected_sha`. Verify after upload. If the available connector cannot ingest binary content safely, commit a text SVG image instead (preserving 700px width) or report the image upload limitation; never upload a filename pretending it is a binary image.

## Final deliverables per scene
- `storyboard/storyboard-part-XX.png` (or `.svg` when honestly labeled), optional `storyboard-full.png`.
- `storyboard/panels.json`, `storyboard/render-checks.json`, `delivery.md`, `scene-state.json` with explicit approval revisions and final artifact references.
- Arabic user reply with visible storyboard if supported and direct GitHub links; explain number of panels, parts, status and any limitation. No need to request a new approval after delivering a correctly generated approved plan; receive revisions as an update.
